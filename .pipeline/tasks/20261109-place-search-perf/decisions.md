# Spec 비평 결정

| 라운드 (최대 2) | 항목 | 수용/기각 | 근거 | 메인 설계자 |
|---|---|---|---|---|
| r1 | C-r1-01 토큰 없는 검색의 경로 간 결과 충돌 | 수용 | 쓸 토큰이 없으면(전부 불용어 포함, 큰따옴표 제거 후 1글자) **정확 일치 포함 장소 검색 전체를 빈 결과**로 통일 → 어느 경로든 같고 현재 구문 검색('"asia"' → 0건)과도 같음. 기각: 커버링 경로만 LIKE로 찾기(지역 건수에 따라 결과가 바뀜). `asia`/`Asia Mart` 전국·작은 지역·큰 지역 + 정확 일치 장소 동반 케이스를 AT-003·004에 고정 | Claude |
| r1 | C-r1-02 LIMIT 응답의 집합 동치 | 수용 | 동치는 **후보 자격**(어떤 장소가 결과가 될 수 있는가)에 대한 계약으로 정의. 동치 fixture는 후보 전체가 `size` 안에 들어오게 구성, 후보가 `size`를 넘는 fixture는 결과 수 = size·전부 후보 자격 충족·중복 없음·정확 일치 우선만 검증. 기각: 전체 정렬로 동일 ID 집합 강제(이 태스크가 없애려는 비용) | Claude |
| r1 | C-r1-03 AT-001 지표가 비례 비용 제거를 증명 못함 | 수용 | 주 지표를 **문장별 `ROWS_EXAMINED`**(`performance_schema.events_statements_history`, 같은 연결)로 변경 = intent의 "읽는 place 행 수" 그대로. 재현 DB 확인: 현재 '카페' 22,845 → 새 FTS 경로 20, 커버링 경로는 훑은 인덱스 항목 수까지 셈(부산 희귀어 40,834 = 지역 전체). 판정: 일치 10배 데이터에서 검색 1회 합계 ≤ 1배 데이터 × 1.2 + 20, 그리고 경로별 절대 상한(FTS ≤ 200, 커버링 ≤ 지역 활성 건수). 커버링 경로의 지역 전체 스캔 상한은 일치 건수가 아니라 **지역 크기**에 묶이고 일치가 늘면 오히려 일찍 멈춤 → intent의 "일치 건수에 비례하지 않음"과 모순 없음, 사람 결정 불필요. 논리 페이지 증가분 ÷ 추가 일치 < 0.1은 보조 지표로 유지 | Claude |
| r1 | C-r1-04 캐시 로딩·invalidate 경합 | 수용 | 세대 객체 + `compareAndSet`으로 invalidate 이전에 시작한 로더의 게시 거부(구현 완료). 추가로 건수 조회를 **`REQUIRES_NEW` 읽기 전용 트랜잭션**에서 실행 → 적재 커밋 전에 시작된 검색 트랜잭션의 옛 스냅숏을 새 세대에 게시하는 경로 차단. latch로 "로딩 중 invalidate" 순서를 고정한 단위 테스트, 로드 실패 후 재시도 테스트 추가. 기각: `synchronized` 직렬화(첫 로딩 동안 검색 대기, 세대 검사로 충분) | Claude |
| r1 | C-r1-05 전체 검색 지연·희귀어 비악화 기준 누락 | 수용 | 구현 전 확정: 로컬 재현에서 검색 1회 전체(정확 일치 + 나머지 문장) 서버 측 지연을 개선 전·후 같은 조건으로 반복 20회 p50·p95, 빈 버퍼 풀 1회 별도 기록. 비악화 기준 = **희귀어·여러 글자 검색어의 개선 후 p95 ≤ 개선 전 p95 + 10ms**(정확 일치 조회 1문 추가분 허용). 건수 캐시 첫 로딩 비용도 기록. 운영 환산은 참고치로만 표기 | Claude |
| r1 | C-r1-06 적재 변경의 검색 반영 | 수용 | AT-005에 실제 importer 경로 시나리오 추가: 파일 A 적재 → 검색 / 파일 B(이름 변경·신규·누락·번호 바뀐 가게) 적재 → 새 이름 검색됨·옛 이름 안 나옴·신규 나옴·누락 가게 안 나옴·재매칭 가게 id 유지, FTS 경로와 커버링 경로 각각 | Claude |
