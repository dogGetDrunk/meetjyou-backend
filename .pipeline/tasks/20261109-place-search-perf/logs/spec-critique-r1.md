### C-r1-01 불용어 토큰이 없는 검색의 FTS·지역 경로 결과 충돌

- 분류: 차단 / 검색 계약
- 관련: REQ-001, REQ-002, REQ-003, REQ-006 / AT-002, AT-003, AT-004, AT-007
- 근거: `spec.md:31`의 현재 `"asia"` 검색 0건, `spec.md:58`의 토큰 없음 → FTS 빈 결과, `spec.md:67`의 커버링 경로 LIKE 조건, `spec.md:70`의 경로 간 결과 동치
- 반례: 검색어 `asia`, 활성 장소 `Asia Mart` 1건, 정확 일치 없음, 같은 지역 필터에서 경로만 강제 변경하는 경우; 명세대로면 FTS는 빈 결과지만 커버링 경로는 `%asia%`에 일치하는 장소 반환
- 영향: 지역 건수 임계값 통과나 캐시 갱신만으로 검색 결과 변경; AT-003의 기존 검색 동치와 AT-004의 경로 동치 동시 충족 불가
- 제안: 토큰 없음의 비정확 일치 처리 정책을 두 경로에 공통 적용하고, 정확 일치 선조회와의 우선순위까지 명시; 현재 계약 유지라면 두 경로 모두 비정확 일치 빈 결과로 통일
- 검증 보완: `asia`/`Asia Mart`의 작은 지역·큰 지역·전국 검색 및 정확 일치 장소가 함께 있는 경우를 AT-003·004에 고정
- 트레이드오프: LIKE만으로 찾을 수 있는 이름도 기존 FTS 의미를 따라 제외하는 선택; 커버링 경로만 검색 범위를 넓히는 대안은 경로 동치와 충돌하므로 기각 필요

### C-r1-02 서로 다른 정렬과 LIMIT을 가진 응답의 집합 동치 판정 불가

- 분류: 차단 / 수용 기준 모순
- 관련: REQ-001, REQ-002, REQ-003, REQ-006 / AT-002, AT-003, AT-004
- 근거: `intent.md:30`의 비정확 일치 순서 비계약, `spec.md:56,67`의 LIMIT 및 ORDER BY 없음, `spec.md:92`의 경로별 순서 차이, `spec.md:124~125`의 결과 집합 동일 요구
- 반례: 같은 지역의 비정확 일치 후보 60건과 `size=20`; 현재 id 순 상위 20건, FTS 상위 20건, 지역 코드·이름 인덱스 상위 20건은 서로 다른 부분집합일 수 있음
- 영향: 의도대로 구현해도 AT-003·004가 실패하거나, 동치 테스트를 맞추려 전체 정렬을 재도입하는 역최적화 위험
- 제안: 동치를 LIMIT 이전의 후보 자격에 관한 계약으로 명확화; 동치 fixture는 후보 전부가 `size≤50` 안에 들어오도록 구성하고, 초과 fixture는 결과 수·후보 적합성·중복 없음·정확 일치 우선만 검증
- 검증 보완: 정확 일치 후보도 size를 초과할 때 특정 ID 집합을 강제하지 않고 정확 일치만 size개 반환하는 AT-002와 연결
- 트레이드오프: 제한 응답의 완전 동일성을 버리고 intent가 허용한 순서 자유 유지; 모든 경로의 동일 ID 집합이 필요하다면 성능과 함께 별도 설계 결정 필요

### C-r1-03 AT-001의 선형 비용 상한으로 intent의 비례 비용 제거를 증명하지 못함

- 분류: 차단 / 성능 완료 기준 약화
- 관련: REQ-002, REQ-003 / AT-001
- 근거: `intent.md:52`의 일치 수 10배에도 place 행 읽기 또는 처리량 비증가 요구와 `spec.md:61,70,122`의 증가분 ÷ 추가 일치 수 < 0.1 요구
- 반례: 읽기 비용이 일치 수의 0.05배인 구현은 N=2,000에서 100페이지, 10N에서 1,000페이지로 정확히 10배 증가해도 AT-001 통과; 기존 구현 RED 확인만으로 이 위양성 제거 불가
- 영향: 작은 계수의 선형 스캔도 합격 가능; 논리 페이지는 커버링 인덱스에서 많은 행 처리를 압축하므로 intent의 place 행 처리량과도 같은 지표가 아님
- 제안: intent를 수정하지 않고 N/10N에서 제한되는 비용의 대상을 명시하고, 실제 place 후보 행 접근/처리의 비증가 또는 명시적 고정 허용 오차를 주 판정으로 고정; 페이지 증가율 < 0.1은 보조 지표로 유지
- 검증 보완: 두 데이터셋의 지역 분포·active 비율·size·선택 경로를 고정하고, 지역 내 유효 결과가 size보다 적거나 없는 경우 및 후보가 결과보다 훨씬 많은 경우도 포함; 전역 카운터 사용 시 다른 테스트와 백그라운드 읽기의 격리 방법 명시
- 추가 확인: REQ-003의 커버링 경로는 지역 전체 스캔 상한을 택한 설계이므로, 이 상한과 intent의 비증가 요구를 어떤 지표로 함께 만족하는지 근거 필요; 수용 기준 완화가 필요하면 사람 결정 게이트 대상
- 트레이드오프: 비용이 작은 상한 스캔과 점근적 비증가는 서로 다른 보장; 어느 쪽인지 흐린 채 회귀 테스트만 통과시키는 대안 기각

### C-r1-04 캐시 로딩과 invalidate 경합 시 오래된 스냅숏 재설치 가능

- 분류: 차단 / 동시성·캐시 무효화
- 관련: REQ-003, REQ-004 / AT-005
- 근거: `spec.md:75~78`의 첫 사용 로딩·@Volatile 스냅숏 교체·적재 성공 직후 invalidate·다음 검색의 새 건수 사용; 로딩과 무효화의 순서 보장 미정의
- 경합: 검색 A가 적재 전 건수 조회 시작 → 적재 커밋 및 invalidate → A가 예전 조회 결과를 스냅숏으로 게시 → 다음 검색 B가 예전 건수를 계속 사용
- 영향: @Volatile만으로는 오래된 로더의 게시 차단 불가; 분기 적재 주기 동안 경로가 잘못 유지될 가능성 및 REQ-004 수용 기준 위반
- 제안: 로딩·무효화를 같은 동기화 경계로 직렬화하거나 세대 번호 확인으로 무효화 이전 로더의 결과 게시를 거부하는 규칙 명시; 통계 조회 트랜잭션이 적재 전 스냅숏을 재사용하지 않도록 읽기 경계도 함께 정의
- 검증 보완: latch 등으로 로딩 중 적재 성공·invalidate 순서를 고정한 단위 테스트와, 적재 커밋 뒤 새 검색의 최신 건수·경로 확인을 AT-005에 추가; 로드 실패 후 재시도도 명시된 실패 계약으로 검증
- 트레이드오프: 단순 직렬화는 드문 초기 로딩 동안 검색 대기 발생, 세대 검사는 복잡도 증가; 상시 오래된 통계를 허용하는 대안은 현재 명시된 다음 검색 갱신 계약과 충돌

### C-r1-05 전체 검색 지연과 희귀어 비악화의 실측·판정 기준 누락

- 분류: 보완 / 성능 증거·완료 조건
- 관련: REQ-001, REQ-002, REQ-003, REQ-004 / AT-001 및 로컬 재현 완료 증거
- 근거: `intent.md:53~55`의 개선 전후 지연 기록·희귀어 비악화 요구, `spec.md:9~25`의 페이지 지표와 운영 환산 중심 표, `spec.md:39~40`의 목표 달성 판단, `spec.md:142`의 최종 재측정
- 누락: 로컬 서버 측 지연의 원시 측정값·반복 수·분포 통계·희귀어 비악화 허용 오차 및 판정 기준; 정확 일치 조회와 나머지 경로를 합친 검색 1회 비용; 첫 검색·invalidate 직후 COUNT 집계 비용
- 영향: 개별 부분 쿼리의 약 570회 물리 읽기를 전체 검색 p95 근거로 해석할 위험; 정확 일치 조회도 별도 비용이 있어 부분 쿼리 환산만으로 합산 응답 목표 확인 불가
- 제안: 같은 약 100만 행·128MB 환경에서 전국/서울 카페 및 희귀어·여러 글자 검색을 이전/이후 동일 조건으로 측정하고, 전체 검색 시간과 부분 쿼리 시간을 구분하여 spec·result에 기록; 차가운 상태·반복 검색·통계 재로딩을 구분하고 비악화 허용 오차를 구현 전에 확정
- 증거 경계: 로컬 측정과 1.7ms 환산은 운영 p95 확정 증거가 아님; 운영 배포·실측은 intent대로 사람 확인 항목 유지
- 트레이드오프: 인프라 변경이나 메모리 인덱스 재설계 요구가 아닌 A 방식의 판단 근거 보강; 페이지 수만으로 지연 완료를 대체하는 대안 기각

### C-r1-06 적재의 네 가지 변경이 실제 검색에 반영되는 수용 기준 누락

- 분류: 보완 / intent 추적성
- 관련: REQ-002, REQ-003, REQ-004, REQ-006 / AT-002, AT-005
- 근거: `intent.md:31,54`의 갱신·재매칭·신규·비활성화 후 검색 반영 요구와 `spec.md:126`의 invalidate 호출·새 통계 사용 위주 AT-005
- 누락: 통계가 갱신되더라도 기존 이름 소멸·새 이름 등장·재매칭 ID 유지·비활성 제외가 검색 응답에서 확인되는 명시적 케이스; 제공 문서만으로 기존 테스트의 해당 검증 여부 확인 불가
- 제안: 실제 importer 경로로 네 변경을 적용하고 커밋 이후 별도 검색 호출에서 최신 이름·지역·ID·active 상태를 검증하는 AT-005 하위 시나리오 명시; 두 검색 경로의 적용 범위도 고정
- 검증 보완: 단순 invalidate mock 검증과 검색 결과 반영 검증을 구분하고, 지역 건수가 그대로인 이름 변경도 포함; 캐시 건수만 맞고 검색이 낡은 상태인 구현의 위양성 차단
- 트레이드오프: 적재 속도·정리 작업은 제외 범위 유지; 검색 반영 보장에 필요한 통합 검증만 추가
