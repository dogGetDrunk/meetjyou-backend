# AT-002-1: pool size 1에서 상세 DTO 생성과 조회수 커밋

- 요구사항: REQ-002
- Given:
  - 별도 Spring 테스트 컨텍스트의 Hikari maximum-pool-size=1, 유한 connection-timeout, 테스트 본문 @Transactional 없음
  - 실제 Post·연관 party/plan/작성자 등 DTO 생성에 필요한 fixture, 요청자 존재, 초기 views=V
  - fixture를 별도 tx에서 저장·커밋; 외부 통신만 격리하고 PostService·PostViewService·Repository·DataSource는 실제 빈
- When:
  - PostController의 현재 비트랜잭션 상세 경로에서 실제 상세 읽기·연관 로딩·DTO 변환·조회수 증가를 수행
  - 응답 이후 독립된 새 tx로 post views·조회 기록 확인
- Then:
  - 상세 요청 성공, DTO 필드 정상, 응답 views=V, DB views=V+1 및 조회 기록 1건 커밋
  - pool timeout·안쪽 커넥션 대기로 인한 조회수 유실 없음, 실제 단일 pool로 동시 2커넥션 요구 불가 입증
  - 단순 200만으로 성공 판정 금지; 현재 중첩 REQUIRES_NEW 구현은 응답이 성공이어도 DB 미증가로 실패
- 이 단계 완료 기준(메인 설계 확정): 보호 파일 작성 + AT ID 표기 + 티켓 확정 인터페이스·케이스 Given/When/Then 일치. 대상 클래스가 아직 없고 `tests/code`가 Gradle 소스셋 밖이라 컴파일·RED 실행 불가는 정상이며 실패 사유가 아님 — 컴파일·RED·GREEN은 구현 워커 gate에서 확인. 기존 초안이 있으면 검토·보완 후 succeeded로 보고
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/post/PostDetailConnectionIntegrationTest.kt`
