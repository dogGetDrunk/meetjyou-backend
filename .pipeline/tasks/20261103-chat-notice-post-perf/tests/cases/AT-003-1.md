# AT-003-1: 공지·약관 수신자 일괄 설정 조회 호출

- 요구사항: REQ-003
- Given:
  - 일반 공지·critical 공지·약관 재동의 각각의 단위 fixture
  - NORMAL/notified=true 사용자: 해당 타입 disabled, 다른 타입만 disabled, 설정 row 없음, enabled=true 각각
  - notified=false·DELETED·PURGED 사용자, 후보 1명·10명 규모 비교
  - UserNotificationPreferenceRepository 및 outbox Repository mock, 기존 per-user isEnabled 호출 추적
- When:
  - 각 발송 본체의 수신자 계산·저장 경로 실행, 타입별 bulk disabled id 조회와 per-user 조회 호출 검증
- Then:
  - 일반 공지·약관 각각 후보 1명·10명일 때 disabled id 조회 정확히 1회, 올바른 NotificationType 전달
  - isEnabled의 유저별 호출 0회; critical 공지는 설정 SELECT 0회 허용, 쿼리를 하더라도 후보 수와 무관하게 최대 1회
  - NORMAL/notified 필터 유지, 동일 타입 false만 제외, 다른 타입 false·row 없음은 포함; critical에서는 해당 타입 false도 포함
  - 기존 title/body/dataJson/dedupKey 조립 값을 캡처하고 변경 전 핸들러의 의미와 동일하게 단언
- 계약: 발송 빈·Repository·예외·핸들러 시그니처와 테스트 지원 계약(StatementInspector 실패 주입·SQL 계수)은 티켓 T-03 `## 확정 인터페이스` 절을 그대로 따름 — 임의 이름·생성자 금지
- 대상: `NoticeBroadcaster(…)`·`TermsReconsentBroadcaster(…, clock)`를 mock Repository로 직접 생성, `findDisabledUserIdsByType` 호출 수·인자와 `NotificationPreferenceService.isEnabled` 미사용 검증 (발송 빈이 `NotificationPreferenceService`를 의존하지 않음)
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/notification/BroadcastPreferenceBatchTest.kt`
