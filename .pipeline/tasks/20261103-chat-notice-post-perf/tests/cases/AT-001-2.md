# AT-001-2: 다양한 읽음 커서·요청자 격리와 실제 집계 SQL 수

- 요구사항: REQ-001
- Given:
  - 실제 H2/JPA 통합 fixture, 요청자 A와 다른 사용자 B, 목록 안 JOINED 방 여러 개
  - 방 R1: A.lastReadMessageId=null, 타인 메시지 3개·A 메시지 2개 → unread 3
  - 방 R2: 기준 메시지 id K를 A cursor로 설정, 타인 메시지 K 이하·초과 2개·A의 K 초과 메시지 포함 → unread 2
  - 방 R3: R2와 다른 cursor, cursor 이하 타인 메시지만 존재 → unread 0; R4: 메시지 없음 → unread 0
  - B의 같은 party JOINED 멤버십은 A와 다른 cursor, B만 JOINED인 목록 밖 방에도 타인 메시지 포함
  - 요청자 JOINED가 아닌 멤버십·목록 밖 방 포함, 기존 목록 선택 규칙 기준으로 제외; 권한 정책 신규 정의 없음
  - fixture commit/flush 후 EntityManager.clear, 쿼리 캐시 간섭 제거; 측정용 SQL 수집기 기록 초기화
- When:
  - 실제 방 목록·unread map 경로 실행, 반환 방 uuid와 각 unread 값 단언
  - 방 0개·1개·10개를 각각 fresh fixture로 구성하고 flush/clear 이후부터 SQL 측정
  - 측정 대상 = unread 집계 SELECT만: `chat_message`를 읽고 `count(`를 포함하는 SELECT (대소문자 무시). 최신 메시지 조회(`findLatestMessagesByRoomUuids`, count 없음)·fixture SQL·타 테이블 SELECT 제외 — 최신 메시지 조회는 이번 범위 밖이라 유지
  - SQL 수집 = 이 테스트 파일 안에 정의한 Hibernate `StatementInspector` 구현(top-level class + companion 상태), `@SpringBootTest(properties = ["spring.jpa.properties.hibernate.session_factory.statement_inspector=<FQCN>"])`로 등록 — `src/test/resources` 변경 없음
- Then:
  - R1=3, R2=2, R3=0, R4=0, B cursor·자기 메시지·목록 밖 메시지 영향 없음
  - A JOINED 목록과 반환 방 집합 일치, 다른 유저 조인 row로 unread 배수 증가 없음
  - unread 집계 SELECT(`chat_message` + `count(`): 방 0개=0회, 1개=정확히 1회, 10개=정확히 1회
  - Repository mock 횟수로 실제 SQL 수 검증을 대체하지 않음; 전체 API SELECT 합계 고정 금지
