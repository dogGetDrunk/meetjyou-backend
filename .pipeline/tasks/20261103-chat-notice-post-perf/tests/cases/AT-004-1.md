# AT-004-1: 공지 API 성공·AFTER_COMMIT 발송 전량 rollback 및 V43

- 요구사항: REQ-004
- Given:
  - 실제 Spring HTTP/MockMvc의 기존 관리자 공지 생성 API, 테스트 메서드 @Transactional 없음
  - 정상 수신자 최소 2명, 실제 broadcaster 프록시·outbox Repository·DB; DiscordAlertService의 운영 알림 호출만 캡처, logger ERROR 캡처
  - 첫 outbox insert flush가 실제 완료된 뒤 다음 저장에서 실패시키는 테스트 fault injection
  - 실패 주입 = 테스트 파일 내 StatementInspector가 2번째 `insert into notification_outbox`에서 RuntimeException (beforeCommit 변형 없음 — 커밋 시점 예외 격리는 AT-004-3 단위 테스트)
  - 독립 Testcontainers MySQL·Flyway 스키마 fixture로 V43 검증, 운영/공유 DB 사용 금지
- When:
  - 실제 공지 생성 API 호출 → 원 tx 커밋 → AFTER_COMMIT 핸들러 → 발송 tx 실패를 순서대로 실행
  - 저장 중 실패(2번째 outbox insert) fixture로 실행, 응답 후 새 tx로 원천 row와 해당 prefix outbox 조회 — tx 종료 시점 실패는 AT-004-3 단위 테스트 담당
  - 같은 예외 클래스의 서로 다른 공지 uuid 실패도 실행해 알림 source가 각각 다른 uuid를 포함하는지 확인
  - MySQL Flyway 적용 후 인덱스 메타데이터에서 notification_outbox.dedup_key의 idx_notification_outbox_dedup_key 확인
- Then:
  - 공지 생성 API 기존 성공 응답, 원천 공지 row 커밋됨, 해당 prefix outbox 0건(먼저 flush된 row도 rollback)
  - 실패 실행별 ERROR 로그와 운영 알림 호출 정확히 1회, 알림에 uuid·예외 클래스·0건 발송·POST /api/v1/notices/{uuid}/broadcast 안내
  - source는 NoticeBroadcast:<uuid> 등 uuid 포함, 서로 다른 uuid는 서로 다른 source; 기발송 INFO skip과 구분
  - 커밋 시점 실패도 catch되어 API로 UnexpectedRollbackException 전파 없음
  - MySQL에서 V43 적용 성공, 인덱스 이름·대상 컬럼 dedup_key·비유니크(NON_UNIQUE=1) 확인, H2/mock으로 대체 금지
- 계약: 발송 빈·Repository·예외·핸들러 시그니처와 테스트 지원 계약(StatementInspector 실패 주입·SQL 계수)은 티켓 T-03 `## 확정 인터페이스` 절을 그대로 따름 — 임의 이름·생성자 금지
- 이 단계 완료 기준(메인 설계 확정): 보호 파일 작성 + AT ID 표기 + 티켓 확정 인터페이스·케이스 Given/When/Then 일치. 대상 클래스가 아직 없고 `tests/code`가 Gradle 소스셋 밖이라 컴파일·RED 실행 불가는 정상이며 실패 사유가 아님 — 컴파일·RED·GREEN은 구현 워커 gate에서 확인. 기존 초안이 있으면 검토·보완 후 succeeded로 보고
