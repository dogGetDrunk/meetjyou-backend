# AT-005-2: 약관 재발송 적격성·유효시점·권한·오류

- 요구사항: REQ-005
- Given:
  - 관리자·일반 사용자 인증 fixture와 실제 API, 테스트 본문 tx 없음
  - 성공: ACTIVE·effectiveAt 과거 또는 정확히 now, 같은 type INACTIVE 버전 존재, prefix outbox 없음
  - now 경계는 발송 코드가 사용하는 기존 시간 접근을 테스트 시계/고정 시점으로 제어, 임의 sleep으로 경계 추정 금지
  - 부적격 독립 fixture: DRAFT, INACTIVE, 같은 type INACTIVE 없는 첫 버전, ACTIVE이지만 effectiveAt 미래, 다른 type의 INACTIVE만 존재
  - 성공 시점 신규 가입/설정 변경 fixture 및 기발송·없는 uuid·비관리자 fixture
- When:
  - POST /api/v1/terms/{termsUuid}/reconsent-broadcast를 각 상태로 실행, 같은 성공 대상 재호출
  - 별도 실제 약관 발행 API에서 미래 effectiveAt 새 버전의 원 이벤트 경로 실행
  - 응답 후 각 outbox·원천 상태를 새 tx에서 조회
- Then:
  - 성공과 effectiveAt=now 경계 모두 200 recipientCount, 재발송 시점 수신자·정상 payload·prefix·outbox 수 일치
  - 부적격 각 경우 409 TERMS_RECONSENT_NOT_APPLICABLE 및 해당 outbox 0건
  - 기발송 409 BROADCAST_ALREADY_SENT, 없는 약관 404 TERMS_NOT_FOUND, 비관리자 403; 모두 outbox 변화 없음
  - 재발송 적격성 판정은 잠금 뒤 같은 발송 tx 내부, API 외부 사전 판정만으로 통과 불가
  - 미래 effectiveAt 원 발송은 기존처럼 발송, 재발송 제한이 원 발행 이벤트에 잘못 적용되지 않음
- 계약: 발송 빈·Repository·예외·핸들러 시그니처와 테스트 지원 계약(StatementInspector 실패 주입·SQL 계수)은 티켓 T-04 `## 확정 인터페이스` 절을 그대로 따름 — 임의 이름·생성자 금지
- 시간 경계: `effectiveAt == now` 허용·`now+1ns` 거부는 같은 파일 안 단위 테스트로 — `TermsReconsentBroadcaster`를 mock Repository + 고정 `Clock`으로 직접 생성해 `resend` 호출. 통합(API) 부분은 now±1h fixture만
- 이 단계 완료 기준(메인 설계 확정): 보호 파일 작성 + AT ID 표기 + 티켓 확정 인터페이스·케이스 Given/When/Then 일치. 대상 클래스가 아직 없고 `tests/code`가 Gradle 소스셋 밖이라 컴파일·RED 실행 불가는 정상이며 실패 사유가 아님 — 컴파일·RED·GREEN은 구현 워커 gate에서 확인. 기존 초안이 있으면 검토·보완 후 succeeded로 보고
