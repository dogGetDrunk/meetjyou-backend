# AT-002-2: 10분 중복·유저 row 없음·응답 views 의미 유지

- 요구사항: REQ-002
- Given:
  - AT-002-1과 같은 실제 상세 통합 컨텍스트, 테스트 본문 트랜잭션 없음
  - 요청자 U, 초기 views=V, U의 첫 조회 기록 없음; 조회/재조회가 확실히 10분 이내가 되도록 기존 시간 fixture 사용
  - 별도 "유저 row 없음" 케이스: 인증 주체는 있으나 해당 uuid의 user row가 없음(존재하지 않는 uuid 주체) — 엔드포인트는 인증 필수라 비로그인 요청은 도달하지 않음, 기존 인증 계약 유지
- When:
  - U로 상세 조회 1회, 이어 10분 이내 같은 게시글 재조회
  - 별도 fixture에서 현재 사용자 없음으로 기존 상세 서비스 경로 실행; 인증 필터를 임의로 공개 전환하지 않음
  - 각 요청 후 새 tx로 저장 상태 확인
- Then:
  - 첫 조회 응답 views=V, DB=V+1; 두 번째 응답 views=V+1, DB도 V+1
  - 10분 이내 중복 조회 기록·카운트 추가 없음, 유저 없음 케이스도 DB views·조회 기록 변화 없음
  - 상세 DTO의 기존 필드 의미 유지, 응답 views는 증가 전 값
- 이 단계 완료 기준(메인 설계 확정): 보호 파일 작성 + AT ID 표기 + 티켓 확정 인터페이스·케이스 Given/When/Then 일치. 대상 클래스가 아직 없고 `tests/code`가 Gradle 소스셋 밖이라 컴파일·RED 실행 불가는 정상이며 실패 사유가 아님 — 컴파일·RED·GREEN은 구현 워커 gate에서 확인. 기존 초안이 있으면 검토·보완 후 succeeded로 보고
