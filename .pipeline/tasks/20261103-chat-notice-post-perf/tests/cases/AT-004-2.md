# AT-004-2: 약관 발행 API 성공·AFTER_COMMIT 발송 전량 rollback

- 요구사항: REQ-004
- Given:
  - 기존 관리자 약관 발행 API·실제 tx·실제 AFTER_COMMIT 핸들러, 테스트 본문 tx 없음
  - 같은 type의 기존 ACTIVE 버전과 발행할 새 버전으로 재동의 이벤트 발생, 정상 수신자 2명 이상
  - 실패 주입 = 테스트 파일 내 StatementInspector가 2번째 `insert into notification_outbox`에서 RuntimeException (beforeCommit 변형 없음 — 커밋 시점 예외 격리는 AT-004-3 단위 테스트)
  - Discord 운영 알림 호출·ERROR 로그 캡처, dispatcher/외부 FCM 격리
- When:
  - 실제 약관 발행 API로 새 버전 발행, 원 tx 커밋 뒤 발송 tx에서 저장 실패
  - API 응답 후 원천 terms 및 해당 prefix outbox를 독립 새 tx에서 조회
  - 같은 예외 클래스·서로 다른 terms uuid 실패에서 알림 source 비교
- Then:
  - 약관 발행 기존 성공 응답, 새 terms row와 발행 상태 커밋됨, 대상 outbox 0건(선행 flush row도 rollback)
  - 실패 실행별 ERROR 로그·DiscordAlertService.sendOperationalAlert 호출 정확히 1회
  - 알림에 terms uuid·예외 클래스·0건 발송·POST /api/v1/terms/{termsUuid}/reconsent-broadcast, source에 해당 uuid 포함
  - 발행 상태 변경이 rollback되어 성공을 가장하지 않음 (새 terms ACTIVE·이전 버전 INACTIVE 커밋 유지)
- 계약: 발송 빈·Repository·예외·핸들러 시그니처와 테스트 지원 계약(StatementInspector 실패 주입·SQL 계수)은 티켓 T-03 `## 확정 인터페이스` 절을 그대로 따름 — 임의 이름·생성자 금지
- 이 단계 완료 기준(메인 설계 확정): 보호 파일 작성 + AT ID 표기 + 티켓 확정 인터페이스·케이스 Given/When/Then 일치. 대상 클래스가 아직 없고 `tests/code`가 Gradle 소스셋 밖이라 컴파일·RED 실행 불가는 정상이며 실패 사유가 아님 — 컴파일·RED·GREEN은 구현 워커 gate에서 확인. 기존 초안이 있으면 검토·보완 후 succeeded로 보고
