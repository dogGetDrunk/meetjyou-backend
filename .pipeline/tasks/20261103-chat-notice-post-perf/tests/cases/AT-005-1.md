# AT-005-1: 공지 재발송 API 성공·중복409·404·403

- 요구사항: REQ-005
- Given:
  - 실제 API 관리자·일반 사용자 인증 fixture, 테스트 본문 tx 없음
  - 기존 공지 저장됐으나 해당 prefix outbox 0건, NORMAL/notified/preference 수신자 행렬
  - 원 발송 시점 이후 신규 NORMAL 가입·설정 변경을 별도 commit한 상태, 재발송 시점 기대 수신자 집합 확정
  - 별도 uuid의 기존 발송 outbox 존재 케이스·존재하지 않는 uuid 케이스·비관리자 케이스
- When:
  - 관리자로 POST /api/v1/notices/{uuid}/broadcast, {} 요청과 critical=false·true를 독립 fixture로 실행
  - 성공 이후 동일 uuid 재호출, 없는 uuid 호출, 비관리자로 유효 대상 호출
  - 각 실행 후 새 tx에서 prefix별 outbox 내용·개수 확인
- Then:
  - outbox 0건이면 HTTP 200 및 recipientCount=실제 기대 수신자 수, outbox 수·recipient 집합 일치
  - {}는 critical=false와 동일, critical=true는 타입 disabled만 무시하고 notified=false/비NORMAL은 계속 제외
  - 재발송 시점의 가입·설정 변경 반영, 원 발송과 title/body/dataJson/dedupKey 규칙 동일
  - 기발송은 409 BROADCAST_ALREADY_SENT, outbox 변화 없음
  - 없는 공지 404 NOTICE_NOT_FOUND, 비관리자 403, 각각 outbox 변화 없음
