# AT-006-1: 쓰기와 겹친 버전 조회가 이전 요약을 캐시에 남기지 못함

- 요구사항: REQ-006
- Given: mockk `AppVersionRepository`·`PlatformStoreUrlRepository`로 만든 `AppVersionService`. `findAllByPlatform(IOS)` 첫 호출은 latch에서 멈췄다가 이전 목록(출시 `1.0.0`, forceUpdate false)을 반환, 이후 호출은 새 목록(출시 `1.0.0` + `2.0.0` forceUpdate true)을 반환. 쓰기용 `findByVersionAndPlatform`·`save` stub
- When:
  1. 조회 스레드: `checkVersion(IOS, "1.0.0")` — mock 안 latch에서 정지 확인
  2. 쓰기 스레드: `setForceUpdate("2.0.0", IOS, true)`(또는 `summaryCache.remove`를 부르는 다른 쓰기 메서드) 호출, 스레드가 끝났거나 `BLOCKED`/`WAITING` 상태가 될 때까지 대기
  3. latch 해제, 두 스레드 join
  4. 메인 스레드: `checkVersion(IOS, "1.0.0")`
- Then:
  - 4의 결과 `latestVersion` = `"2.0.0"`, `updateRequired` = true (새 목록 기준)
  - 별도 순차 케이스: 쓰기 → 조회 결과가 새 목록 기준 (동작 유지)
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 기준 실행: red
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/version/AppVersionCacheStaleTest.kt`

## 회귀·증거

- base RED: `getOrPut`은 계산 밖에서 `remove`가 먼저 끝나고 조회가 이전 요약을 넣어 4가 `1.0.0`·updateRequired false
- 스레드·latch 대기에 제한 시간 필수(교착 시 실패로 끝나야 함). 기존 `AppVersionServiceTest` 별도 통과
