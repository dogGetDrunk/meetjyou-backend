# AT-003-2: 실제 스케줄러 경로의 예약 작업 예외 → Discord 운영 알림

- 요구사항: REQ-003
- Given: `@SpringBootTest`(test 프로필, 스케줄링 활성), `@MockBean` `DiscordAlertService`·`WithdrawnUserPurgeService` + 외부 의존 `@MockBean`(기존 `AuthSecurityReproIntegrationTest` 패턴). 다른 예약 작업도 같은 mock을 부를 수 있으므로 알림 검증은 총 횟수가 아니라 인자 매칭
- When:
  1. 컨텍스트의 `ScheduledAnnotationBeanPostProcessor`(또는 `ScheduledTaskHolder`)가 `@Scheduled` 작업 등록에 쓰는 스케줄러 인스턴스를 꺼냄(예: registrar의 `scheduler`)
  2. 컨텍스트의 `scheduledTaskScheduler` 빈(이름으로 조회, `ThreadPoolTaskScheduler`)으로 고유 메시지(UUID 포함)의 `IllegalStateException`을 던지는 작업 실행, 이어서 같은 스케줄러로 latch를 내리는 정상 작업 실행
  3. `WithdrawnUserPurgeService.findPurgeTargets`가 이미지 없는 대상 1명, `purge`가 고유 메시지 예외를 던지도록 stub → `WithdrawnUserPurgeScheduler.purgeExpiredWithdrawals`를 2의 스케줄러로 실행
- Then:
  - 1의 스케줄러 = `scheduledTaskScheduler` 빈(동일 인스턴스), `messageBrokerTaskScheduler`와 다른 인스턴스 (C-r1-06)
  - 2: 제한 시간 안에 `sendOperationalAlert(source = any, exceptionClass = "IllegalStateException", summary에 고유 메시지 포함)` 호출, 이후 정상 작업 latch 해제됨(스케줄러 계속 동작)
  - 3: 제한 시간 안에 `exceptionClass` = 주입 예외 simpleName, summary에 그 고유 메시지가 포함된 `sendOperationalAlert` 호출
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 기준 실행: red
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/config/ScheduledTaskAlertIntegrationTest.kt`
