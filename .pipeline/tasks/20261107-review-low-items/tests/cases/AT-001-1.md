# AT-001-1: JwtAuthFilter — 공개 GET은 실패 토큰이어도 익명 진행

- 요구사항: REQ-001
- Given: 기존 3인자 생성자로 만든 `JwtAuthFilter`(mockk `JwtProvider`·`UserRepository`, 실제 `AuthenticatedUserCache`), 매 케이스 `SecurityContextHolder.clearContext()`
- When: `MockHttpServletRequest`로 아래 조합 실행
  - 공개 GET(`/api/v1/notices`, `/api/v1/ios/versions/check`) + `validateAccessTokenOrThrow`가 `CustomExpiredJwtException` / `InvalidJwtException`("Not an access token", refresh 토큰 상황)을 던짐
  - 공개 GET + 토큰 검증 통과하나 유저 조회 결과 탈퇴(status DELETED) → `UserWithdrawnException`
  - 공개 GET + 유효 토큰·NORMAL 유저
  - 비공개 GET(`/api/v1/users/me/profile`) + 만료 / 형식 오류
  - 공개 경로의 POST(`POST /api/v1/notices`) + 만료
- Then:
  - 공개 GET + 실패 3종: 체인 호출됨, 응답 상태 미설정(200 기본값)·본문 비어 있음, `SecurityContext` 인증 정보 null
  - 공개 GET + 유효 토큰: 체인 호출, `SecurityContext` 인증 정보 설정·principal uuid 일치 (동작 유지)
  - 비공개 GET: 체인 미호출, 401 + 본문 `errorCode` = `EXPIRED_TOKEN` / `INVALID_JWT` (동작 유지)
  - 공개 경로 POST + 만료: 체인 미호출, 401 `EXPIRED_TOKEN` (동작 유지)
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 기준 실행: red
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/auth/jwt/JwtAuthFilterPublicReadTest.kt`

## 회귀·증거

- base RED: 공개 GET + 실패 토큰 케이스(현재 401 응답 후 체인 중단). 나머지는 동작 유지
- `PublicReadEndpoints` 등 새 인터페이스 참조 금지(base 컴파일 유지) — 매칭 경계는 AT-001-2 담당
