# Intent

## 해결할 문제

- #296 관광공사 하루 호출 한도 초과(게이트웨이 `returnReasonCode=22`) 뒤에도 `TourPlaceSearch.search` 가 검색마다 `searchKeyword2` 를 다시 호출
  - 소진 뒤 그날 남은 검색이 전부 외부 왕복 지연과 warn 로그 1줄씩을 떠안음
  - 개발 계정 한도 = 기능별 하루 1,000회
- #297 시군구 지역 필터 검색에서 관광공사 결과 대부분이 버려짐
  - `TourApiClient.buildUri` 는 시도(`lDongRegnCd`)만 넘기고, `TourPlaceSearch` 가 시도 전체 1페이지(`numOfRows=size`)를 받은 뒤 `regionCatalog.isWithin` 으로 시군구를 다시 거름
  - 예: `region=11110`(종로구), `q=박물관` → 서울 전체 20건 중 종로 몇 건만 남음. 같은 검색의 가게 묶음은 종로 안에서 20건을 채워 두 묶음 재현율이 크게 어긋남

## 의도

- 한도 초과를 받으면 일정 시간 관광공사 호출을 멈춰, 한도가 없는 동안의 무의미한 외부 왕복과 로그를 없앰
- 일반 시군구 필터에서는 관광공사에도 시군구 코드를 넘겨, 관광지 묶음이 그 시군구 안에서 결과를 채우게 함

## 포함 범위

- 한도 초과 감지: 게이트웨이 XML `returnReasonCode=22` 와 JSON `resultCode=22` 를 둘 다 "한도 초과"로 구분 (지금은 `RESULT_CODE` 하나로 뭉침)
- 호출 중지: 한도 초과를 받은 시점부터 **"다음 KST 자정"과 "지금 + 1시간" 중 이른 시각**까지 `searchKeyword2` 를 호출하지 않음
  - 중지 동안 응답은 지금과 같은 `tourStatus=FAILED`, 빈 `tourPlaces` (응답 형식 변경 없음)
  - 중지 동안 검색마다 warn 로그를 남기지 않음, 중지를 시작할 때 warn 1줄(재개 시각 포함)
  - 상태는 프로세스 메모리 플래그 (앱 인스턴스 1대). 응답 캐싱이 아니므로 ADR-0004(저장, 캐싱 없음)와 충돌 없음
- 시군구 코드 전달: 지역 필터가 **일반 시군구**(부모가 시도이고 하위 일반구가 없는 시군구, 217개)일 때 `lDongSignguCd` 도 함께 전달
  - 일반구(39개)와 일반구를 둔 시(13개)는 지금처럼 시도만 전달 (관광공사가 이들을 어떤 시군구 코드로 내려주는지 미확인)
  - 결과 재필터(`isWithin`)는 그대로 유지 → API가 `lDongSignguCd` 를 무시해도 지금과 같은 결과
- 단위 테스트: 한도 초과 구분, 중지와 재개 경계(자정, 1시간), 중지 중 호출 0회, 시군구 코드 전달 여부(일반 시군구, 일반구, 일반구를 둔 시, 시도, 필터 없음)
- `.claude/rules/place.md` 관광공사 절에 중지 규칙과 시군구 전달 규칙 반영

## 제외 범위

- 유저별 호출 제한, 검색 응답 캐시 (ADR-0004 캐싱 금지, 문제 관측 전)
- 응답에 한도 초과 전용 상태값 추가 (`tourStatus` 계약 변경, 앱 영향)
- 여러 인스턴스 간 중지 상태 공유 (인스턴스 1대)
- 운영 계정 신청, 프론트 검색 호출 방식 (11/24 회의에서 "입력 완료 시 호출"로 결정됨, 백엔드 작업 아님)
- 일반구와 일반구를 둔 시의 시군구 코드 전달 (실제 응답 확인 후 별도 판단)

## 성공 기준

- 한도 초과 응답(XML 22, JSON 22) 1회 뒤 중지 기간 동안 `TourPlaceSource.searchKeyword` 호출 0회, 응답은 `tourStatus=FAILED`
- 중지 종료 시각 = min(다음 KST 자정, 한도 초과 시각 + 1시간), 그 시각 이후 첫 검색은 다시 호출
- 한도 초과가 아닌 실패(네트워크, HTTP 상태, 다른 resultCode)는 지금처럼 중지 없이 다음 검색에서 재호출
- 일반 시군구 필터(예: `11110` 종로구)에서 요청 URI에 `lDongRegnCd=11` 과 `lDongSignguCd=110` 이 함께 들어감, 일반구(예: `41111`)와 일반구를 둔 시(예: `41110`), 시도, 필터 없음에서는 `lDongSignguCd` 없음
- `agent-pipeline gate` 통과 (`./gradlew test` 와 detekt 포함)

## 결정 필요 사항 (승인 시 함께 확정)

- **중지 기간 = min(다음 KST 자정, +1시간)**
  - 기각: KST 자정까지만 중지(이슈 제안) — 한도 리셋 시각이 자정이라는 근거가 공식 문서로 확인되지 않음. 리셋이 자정보다 늦으면 자정 직후 22를 다시 받고 다음 날 자정까지 하루를 통째로 잃음
  - 기각: 고정 1시간 쿨다운만 — 자정 리셋이 맞다면 최대 1시간 늦게 복구됨
  - 비용: 자정 전까지 시간당 1회, 최대 약 23회의 헛호출 (각 검색 1건만 왕복 지연)
- **시군구 코드 전달은 일반 시군구 217개로 한정**
  - 기각: 일반구와 시까지 전달 — 관광공사 항목이 일반구 코드(예: `111`)로 오는지 시 코드(`110`)로 오는지 미확인, 틀리면 결과가 0건이 되어 지금보다 나빠짐
  - 선행 확인 권장: 실제 키로 `lDongSignguCd` 를 넣은 호출 1회 (서비스키는 시크릿이라 에이전트가 쓰지 않음, 사람이 확인). 확인 전에도 재필터 유지로 회귀 없음
