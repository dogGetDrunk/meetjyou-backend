# Intent

> 메인 설계 에이전트가 사람과 대화로 작성. 승인 기록은 `approval.json`(`agent-pipeline approve-intent`), 승인 후 이 파일 수정 금지.

## 해결할 문제

- 모집글 `location`, 파티·여행계획서 `destination`이 자유 문자열(최대 50자) → 같은 곳도 표기가 제각각이라 지역 집계·지역 범위 검색·"많이 선택된 여행지" 추천 불가
- 78주차 회의(10/20) 결정: 여행지를 관광지·가게 단위까지 제공, 공공 데이터를 합친 자체 검색 API로 제공 (카카오 장소 검색은 결과 저장 금지라 집계·참조에 못 씀)
- 11/6 결정(민석): 여행지 = 지역(필수) + 장소(선택) 계층, 지역은 시·도 > 시·군·구
- 관광공사 데이터는 DB 저장에 '서버구축(DB저장) 방식' 승인이 필요하고 아직 신청 전 → 1차는 지역 + 소상공인 데이터로 먼저 구축

## 의도

- 지역 목록과 소상공인 가게 데이터를 우리 DB에 적재하고, 검색창 하나로 지역·장소를 함께 찾는 검색 API 제공
- 모집글·파티·여행계획서의 대표 여행지를 자유 문자열 대신 지역·장소 참조로 저장 → 이후 집계·추천·직접 입력·관광공사 적재가 같은 모델 위에 올라감

## 포함 범위

1. **지역 목록 적재**
   - 시·도 > 시·군·구 2단계, 5자리 법정동 시·군·구 코드를 키로 사용
   - 일반구(예: 수원시 장안구)는 시(수원시) 아래에 두고, 시를 고르면 하위 구까지 함께 검색 (노션 안건 권장안)
   - 2026-07 전남광주통합특별시, 인천·화성 신설 구 반영
2. **소상공인 가게 적재 (ADMIN API)**
   - ADMIN 권한 API 호출 → 서버가 공공데이터포털에서 zip(약 349MB, 시·도별 CSV 16개)을 내려받아 한 줄씩 읽어 업종 필터 후 upsert
   - 업종: 음식점·카페·술집·숙박 + 여행자용 쇼핑 소분류. 제외: 구내식당, 무도유흥주점, 기숙사·고시원
   - 재실행 가능: 같은 가게는 상가업소번호로 갱신, 새 파일에 없는 가게는 검색에서 빼고 "현재 영업 정보 없음" 상태로 표시 (참조 중인 글은 유지)
   - 실행 중 재호출 거부, 실행 결과(처리·추가·갱신·제외 건수) 로그
3. **여행지 검색 API**
   - 검색어 하나로 지역과 장소를 함께 반환, 장소 결과는 소속 지역(시·도·시·군·구)을 포함 → 장소를 고르면 지역 자동 채움
   - 지역 범위 필터(시·도 또는 시·군·구, 시는 하위 일반구 포함), 페이지 크기 상한
   - DB 검색(MySQL ngram FULLTEXT 등)으로 구현, 응답에 이미지 없음
4. **대표 여행지 참조 변경**
   - 모집글·파티·여행계획서 생성·수정 요청: 지역 코드 + 장소 ID(선택). 전환 기간 동안 지역 코드도 선택, 기존 문자열 필드 병행(결정 1)
   - 기존 행은 "미지정" 지역으로 채움(결정 2)
   - 장소를 주면 그 장소의 지역과 요청 지역이 맞는지 검증(불일치·없는 코드 → 400)
   - 조회 응답: 지역(코드·시·도명·시·군·구명) + 장소(ID·이름·영업 정보 없음 여부)
   - 모집글 → 파티 동기화(`syncFromPost`)도 참조 기준으로

## 제외 범위

- 관광공사 데이터 적재·동기화 (서버구축 방식 승인 후 별도 태스크)
- 여행계획서 **마커**의 장소 참조 변경 (노션 TODO에는 있으나 이번엔 대표 여행지만, 마커는 다음 태스크)
- 직접 입력 장소 등록, 관리자 승인·거절·합치기 API, 도로명주소·좌표 API 연동
- 분기 자동 갱신 스케줄(`@Scheduled`), 사라진 가게와 직접 입력 장소의 겹침 후보 찾기
- 추천 집계("많이 선택된 여행지")
- 운영 DB 실제 적재 실행과 운영 검색 지연 실측 → 배포 후 사람이 ADMIN API로 실행(에이전트는 운영 접근 금지)
- 메모리 인덱스 검색 (실측 결과가 기준을 넘을 때 다음 태스크에서 검토)
- 해외 여행지

## 결정 사항 (2026-11-09, 사용자)

1. **API 계약 전환 = 전환 기간 방식** — 생성·수정 요청은 기존 `location`/`destination` 문자열과 지역·장소 참조를 둘 다 받음(참조는 선택), 응답은 기존 문자열 필드 유지 + 참조 필드 추가. 앱 반영 후 문자열 제거는 별도 태스크
   - 기각: 한 번에 교체 + 강제 업데이트 — 프론트 합의 전이라 현재 앱의 글 작성이 깨짐
2. **기존 행 = "미지정" 지역으로 채움** — 지역 목록에 "미지정" 행 하나를 두고 기존 행을 그 지역으로 채움. "미지정"은 검색·집계 대상에서 제외
   - 기각: 실제 지역(예: 서울) 기본값 — 그 지역 집계·추천이 테스트 데이터로 부풂 / NULL 유지·삭제
3. **쇼핑 소분류 = 후보 8개 그대로** — 편의점·기념품점·화장품·약국·예술품·서점·시계·귀금속
4. **지역 단계·일반구 표시** — 11/9 회의 미개최로 미결. 백엔드는 시·도 > 시·군·구, 일반구를 시 아래에 두는 모델로 진행하고 화면 표기만 열어 둠(응답에 시·군·구명과 상위 시 정보를 함께 제공)
5. **관광공사 제외 근거** — 콘텐츠랩 저작권 정책상 DB 저장은 기본 금지, '서버구축(DB저장) 방식' 승인(개발 계정 키 필요, 검토 3~5일+) 전. 장소 테이블에 출처 구분을 두어 승인 후 적재기만 추가하도록 설계

## 성공 기준

- 지역 목록에 현행 시·도·시·군·구(전남광주·인천·화성 신설 구 포함)가 들어가고, 일반구가 소속 시 아래에 연결됨
- ADMIN API로 소상공인 zip을 적재하면 대상 업종만 들어가고 제외 업종은 0건, 같은 파일을 다시 적재해도 건수가 늘지 않음
- 다음 파일에서 빠진 가게는 검색 결과에서 사라지고, 그 가게를 참조한 글은 "영업 정보 없음"으로 조회됨
- ADMIN이 아닌 사용자의 적재 호출은 403, 실행 중 재호출은 409
- 검색어 하나로 지역·장소가 함께 나오고, 장소 결과에 소속 지역이 포함됨. 시 단위 필터는 하위 일반구 장소까지 포함
- 모집글·파티·계획서를 지역(+장소) 참조로 생성·수정·조회 가능, 없는 코드·지역 불일치는 400
- 참조 없이 기존 문자열만 보내는 현재 앱 요청도 그대로 성공(응답 기존 필드 유지)
- 마이그레이션 후 기존 행은 모두 "미지정" 지역을 가리키고, "미지정"은 검색 결과에 나오지 않음
- 단위+통합 테스트 포함 `./gradlew test build`(agent-pipeline gate) 통과
- 배포 후 사람 확인 항목(이 태스크 완료 조건 아님): 운영 적재 소요 시간·메모리, 검색 p95 지연 실측값을 result에 기록
