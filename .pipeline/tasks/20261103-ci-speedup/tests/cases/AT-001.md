# AT-001: 문서 전용 PR 판정·전체 빌드 fallback·필수 체크 보존

- 요구사항: REQ-001
- Given: 임시 Git 저장소의 실제 base·head 커밋, 독립 사례별 파일 변경 및 구현 대상 판정 스크립트
- When: `scripts/ci-docs-only.sh <base> <head>` 실행 및 PR/main 워크플로 조건 확인
- Then: 아래 15개 판정 사례의 stdout 정확히 한 줄·기대값 일치·exit 0, 정책 검증 항상 실행 및 안전한 전체 빌드 fallback
- 작성자: 보조 설계
- 코드 작성자: 별도 test-writer 세션
- 보호 대상 테스트 파일:
  - `scripts/ci-docs-only.test.sh`

## 자동화 판정 사례 — 실제 Git diff 포함

- 각 행을 별도 baseline에서 재현, 실제 커밋의 base·head 사용; 정적 파일 목록을 함수에 전달하는 대체 테스트 금지
- 파일 수집은 구현 스크립트가 수행; 테스트는 git rename 검출을 끄는 옵션을 대신 주입하여 결함을 숨기지 않음
- 모든 행에서 stdout `true` 또는 `false` 한 줄 및 exit 0 검증, 실패 시 사례 이름 출력 후 테스트 스크립트 exit 1

| 사례 | Given / 변경 | When | Then stdout |
|---|---|---|---|
| docs_allowlist | `docs/a.md`·`.pipeline/tasks/x/intent.md`·`README.md`·`.claude/rules/party.md` 수정만 | base→head 판정 | true |
| mixed_code | 허용 문서 변경 + `src/main/kotlin/A.kt` | base→head 판정 | false |
| source_markdown | `src/main/resources/notes.md` 단독 | base→head 판정 | false |
| tools_markdown | `tools/agent-pipeline/GUIDE.md` 단독 | base→head 판정 | false |
| scripts_markdown | `scripts/notes.md` 단독 | base→head 판정 | false |
| workflow_markdown | `.github/workflows/README.md` 단독 | base→head 판정 | false |
| detekt_config | `config/detekt/baseline.xml` 단독 | base→head 판정 | false |
| build_config | `build.gradle.kts` 단독 | base→head 판정 | false |
| pipeline_config | `.pipeline/project.yaml` 단독 | base→head 판정 | false |
| rename_code_to_docs | 동일 내용 파일 `src/main/kotlin/A.kt`→`docs/A.md` 이동 | rename 커밋 판정 | false |
| rename_docs_to_code | 동일 내용 파일 `docs/A.md`→`src/main/kotlin/A.kt` 이동 | rename 커밋 판정 | false |
| rename_docs_to_docs | 동일 내용 파일 `docs/a.md`→`docs/b.md` 이동 | rename 커밋 판정 | true |
| delete_code | 기존 `src/main/kotlin/A.kt` 삭제만 | 삭제 커밋 판정 | false |
| empty_diff | base=head | 동일 ref 판정 | false |
| invalid_ref | 존재하지 않는 ref | 잘못된 ref로 판정 | false |

- test-writer: 스크립트 안에 `AT-001` 식별자 포함; 임시 저장소 local Git identity 설정, 실제 저장소·전역 Git 설정 변경 금지, trap으로 자신이 만든 임시 파일 정리
- `bash scripts/ci-docs-only.test.sh`: 모든 사례 성공 exit 0, 하나라도 실패하면 사례 이름과 exit 1

## 워크플로 정적 검토

- Given: `.github/workflows/ci.yml`의 PR 및 main push trigger
- When: checkout·판정·정책·JDK·Gradle·리포트 조건을 함께 검토
- Then:
  - job 이름 `build-and-test` 및 기존 정책 검사 유지
  - PR의 merge commit·첫 부모를 비교 가능한 checkout 깊이, 판정 인자 `HEAD^1 HEAD`
  - 판정 step `continue-on-error: true`, step 성공 및 출력 정확히 `true`인 PR에서만 Gradle 관련 세 단계 생략
  - 스크립트 부재·실패·출력 없음·true 외 출력은 전체 빌드로 연결
  - main push는 판정 step 미실행 및 전체 빌드
  - `Verify pipeline policy`는 조건 없이 실행, 판정 스크립트 테스트도 실행, 정책 검사 실패 시 문서 PR도 실패
- 자동화 범위: 15개 Git 판정 사례; 위 조건의 정적 검토와 실제 실행 증거를 스크립트 단위 테스트 통과로 대체 금지
- 실패 주입용 일회성 PR 실행표 테스트 제외(C-r1-03 결정), 기존 리포트 실패 업로드 정책 보존

## 실제 실행 수용 — 메인 설계자

- Given: T-01 적용 후 결과 PR의 문서 전용 변경
- When: 실제 PR CI 1건 실행 로그·step 상태·job 시간 확인
- Then: `build-and-test` 성공, JDK·Gradle·리포트 생략, CI 1분 이내; run ID와 증거 result.md 기록
- Given: T-02 구현 코드 PR
- When: 실제 PR CI 1건의 로그 확인
- Then: 전체 Gradle step 실행; run ID와 증거 result.md 기록
- 실제 실행 증거가 없으면 해당 수용 항목 미검증으로 남김, 스크립트 성공으로 CI 효과 달성 주장 금지
