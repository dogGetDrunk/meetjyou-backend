## 목표

- REQ-002 / AT-002: 컨테이너 반복 준비 비용 제거, 기존 테스트의 빈 스키마·마이그레이션 버전·락 대기 관찰 의미 보존

## 구현 범위

- 생성: `src/dockerTest/java/com/dogGetDrunk/meetjyou/support/SharedMySql.kt`
- 이미지 태그 `mysql:8.0.41` 상수를 지원 코드 한 곳에만 배치, 테스트 JVM당 컨테이너 1개 지연 기동
- 캐시된 Spring 컨텍스트의 커넥션 풀 수용을 위해 `max_connections`를 기본 151보다 크게 설정(명세 예: 500)
- `newDatabase()`마다 충돌 없는 이름의 빈 database 생성 및 해당 database를 지정한 jdbcUrl·username·password·performance_schema root 접속 제공
- 반환 접속 정보의 `countLockWaits()`는 `performance_schema.data_lock_waits.REQUESTING_ENGINE_LOCK_ID = performance_schema.data_locks.ENGINE_LOCK_ID` 조인 및 `data_locks.OBJECT_SCHEMA`를 자기 database로 제한
- 타입명·필드명 등 명세가 구현 재량으로 둔 세부는 선작성 보호 테스트의 실제 호출 계약과 정합 유지, 새로운 외부 API 설계 추가 금지
- 기존 16개 스펙의 컨테이너 생성·start·stop을 `SharedMySql.newDatabase()`로 교체; 스펙별 접속 정보 1개 유지
- Spring: `@DynamicPropertySource`에 새 database 접속 정보 등록; 비 Spring: Flyway·DriverManager의 접속 정보 교체
- `MySQLContainer<*>`를 받던 private 헬퍼는 접속 정보 타입을 받도록 시그니처만 변경
- 전역 락 대기 카운트 6개 스펙의 `countLockWaits()` 사용: `PostLockFreshRead`, `PostUpdatePartyCompleteDeadlock`, `PartyAggregateDeadlock`, `SocialAccountConcurrency`, `RefreshTokenRotationConcurrency`, `UserUniqueRace`
- `JdbcSessionStateRoundTripDockerTest`의 `SELECT_DIGESTS` 조회에 자기 database의 `SCHEMA_NAME` 조건 추가
- `PartyAggregateDeadlockDockerTest`의 `SHOW ENGINE INNODB STATUS`는 진단 로그이므로 유지, 타 database의 교착 로그 혼입 허용
- 공유 컨테이너 stop 호출 금지, Ryuk에 종료 위임; Kotest 스펙 순차 실행 유지
- 보호 테스트 생성: `src/dockerTest/java/com/dogGetDrunk/meetjyou/support/SharedMySqlDockerTest.kt`; test-writer의 코드 복사만 허용
- 기존 테스트 시나리오·단언·상수 값 변경 금지; 명시된 접속 교체·이미지 상수 중앙화·database 관찰 한정만 허용
- 제외: 같은 database TRUNCATE 재사용, 전역 상태 초기화로 테스트 통과, 단언 완화, reuse·ServiceConnection 도입, 컨텍스트 통합, 병렬 실행·maxParallelForks, 단위 test 최적화
- 자기 database로 관찰 범위를 한정할 수 없는 사례 발견 시 변경 중단·근거 기록 및 escalation, 우회 설계 확정 금지
