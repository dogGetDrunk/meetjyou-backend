## 목표

- REQ-001 / AT-001: 허용 목록에만 속하는 문서 전용 PR의 반복 빌드 생략, 필수 체크·정책 검증·main push 전체 빌드 보존

## 구현 범위

- 판정 스크립트에서 `git diff --no-renames --name-only <base> <head>` 직접 실행
- 허용 경로: `docs/**`, `.pipeline/tasks/**`, 저장소 루트 `*.md`, `.claude/rules/**/*.md`만; 디렉터리 경계 및 루트 한정 보존
- Git 실패·변경 0개·허용 목록 밖 경로 존재 시 `false`, 정상 문서 변경만 `true`; stdout 한 줄 및 exit 0 보존
- rename 검출 해제에 따른 삭제·추가 양쪽 경로 검사; 코드→문서 이동의 코드 삭제 누락 금지
- PR checkout에서 merge commit과 첫 부모 비교 가능한 이력 확보(예: `fetch-depth: 2`); `HEAD^1 HEAD`로 판정
- 판정 step에 `continue-on-error: true`, PR에서만 실행; 출력 미등록·실행 실패·true 외 출력 시 전체 빌드
- 생략 조건에 PR 이벤트·판정 step 성공·출력 정확히 `true` 모두 포함; 스크립트가 출력 후 실패한 경우도 전체 빌드
- 같은 생략 조건을 JDK 설정·`./gradlew build dockerTest`·테스트 리포트 업로드에 적용; 기존 리포트의 실패 시 업로드 동작 등은 보존
- `Verify pipeline policy` step은 문서 PR에도 항상 실행, 기존 정책 검사 명령 유지 및 `bash scripts/ci-docs-only.test.sh` 추가; 정책 검사 실패 시 job 실패
- `push: main`은 판정 step 생략 및 전체 빌드; job 이름 `build-and-test` 유지
- 보호 스크립트는 test-writer의 선작성 코드 복사만 허용, 구현자가 수정하여 통과시키기 금지
- 제외: workflow-level `paths-ignore`, 외부 paths-filter action, job 분리·캐시·브랜치 보호 변경, dockerTest 변경, 일회용 PR을 이용한 실패 주입 실험

## 참고할 기존 패턴

## 실행·검증 순서

1. AT-001의 보호 스크립트 복사 및 수정 전 실행 결과 기록; 현재 구현이 없거나 잘못된 경우 실패 원인 보존
2. 판정 스크립트 구현 및 workflow 연결; 기존 필수 정책 검증 제거 금지
3. `bash scripts/ci-docs-only.test.sh` 실행, 표의 15개 사례 전부 통과 및 exit 0 확인
4. workflow 정적 검토: PR + 판정 성공 + 정확한 true에서만 세 Gradle 관련 단계 생략, push main 전체 빌드, 정책 검증 항상 실행 및 실패 전파 확인
5. 공통 gate `./gradlew test build` 및 intent의 `./gradlew build dockerTest` 실행, 실제 결과 기록; 실패를 자체 리뷰로 대체 금지
6. 머지 후 메인 설계자의 문서 PR·코드 PR 실행 증거 확인으로 운영 수용 기준 보완
