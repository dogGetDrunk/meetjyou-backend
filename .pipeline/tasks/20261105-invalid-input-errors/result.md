## 핵심 결정과 기각한 대안

- **마커 최대 200개** — 하루 10~20곳 × 10일 내외 기준. 100(긴 여행 부족)·300(차단 효과 대비 이득 없음) 기각. 프론트 합의 전 선구현, 노션 태스크 안건에 "논의 필요" 기록
- **`Idempotency-Key` 255자(DB 컬럼과 동일)** — 36자 UUID 고정은 프론트 발급 방식 확정 전 형식 제약이라 기각
- **키 길이는 서비스에서 검증** — 헤더 `@Size`(Spring 메서드 검증)는 `@RequestBody` 검증 오류까지 `HandlerMethodValidationException`으로 바뀌어 응답 형식이 달라질 위험이 있어 기각
- **`resolveAfterConflict` nullable + 컨트롤러 `?: throw e`** — 키 행이 없으면 키 경합이 아니므로 원래 예외를 기존 핸들러(유니크 매핑 409 / 미매핑 500)에 맡김
- **Apple 서명 우선** — 서명 안 된 토큰 클레임으로 분기·로그하지 않음. 미지 `kid` JWKS 재조회는 `AppleJwksCache`가 30초당 2회로 제한해 Apple 호출 증폭 없음
- **생성 응답 코드는 기존 200 유지** — spec 초안의 201은 메인 설계자 오기, 상태 코드 변경은 범위 밖 (B-r1-01)
- **AT-003-1만 base 컴파일 실패를 RED로 인정** — 테스트가 확정 인터페이스(nullable 반환)를 직접 stub, 리플렉션 등으로 재작성하면 테스트가 흐려져 기각 (B-r1-02)
- 비평 4건(C-r1-01~04)·지시서 점검 5건(B-r1-01~03, B-r2-01~02) 결정은 `decisions.md`
