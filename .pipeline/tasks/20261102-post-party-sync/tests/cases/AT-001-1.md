# AT-001-1: 모집글 네 필드의 파티 동기화

- 요구사항: REQ-001, REQ-004
- Given:
  - 작성자 H의 PLANNING/OPEN 파티, joined=3, Post.capacity=Party.capacity=3
  - Post·Party 일정 `2030-05-01T00:00:00Z`~`2030-05-03T00:00:00Z`, location/destination=`Busan`, title=`Old title`
  - plan 유지·교체·해제의 세 변형, plan이 없고 그대로인 변형 포함
- When:
  - H가 updatePost로 capacity=10, 일정 `2030-06-01T00:00:00Z`~`2030-06-05T00:00:00Z`, location=`Jeju`, title=`New title` 요청
- Then:
  - 성공 후 새 트랜잭션 재조회에서 Post/Party capacity=10, 두 일정이 요청값과 같고 Post.location=Party.destination=`Jeju`
  - joined=3 유지, 요청한 plan 연결의 기존 동작 유지
  - 단위 verifyOrder에서 모든 변형마다 `lockPartyOfPost(postUuid) → postRepository.lockByUuid(postUuid)` 확인; 일반 findByUuid 경로 미사용
- 작성자: 보조 설계
- 코드 작성자: 별도 세션의 Terra
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/post/UpdatePostPartySyncServiceTest.kt`
  - `src/test/java/com/dogGetDrunk/meetjyou/post/PostPartySyncIntegrationTest.kt`
  - `src/test/java/com/dogGetDrunk/meetjyou/post/UpdatePostPlanSyncTest.kt`
- 테스트 종류: 단위 Kotest BehaviorSpec + H2 통합(SpringExtension)

## 구현·검증 지침
- 기존 UpdatePostPlanSyncTest의 attach/detach 시나리오를 유지하며 lockByUuid stub으로 갱신
- H2 HTTP PUT 또는 프록시 서비스 호출로 실제 커밋/재조회 검증; DTO의 추가 필드는 기존 유효값 유지
- `./gradlew test --tests '*UpdatePostPartySyncServiceTest' --tests '*PostPartySyncIntegrationTest' --tests '*UpdatePostPlanSyncTest'`
