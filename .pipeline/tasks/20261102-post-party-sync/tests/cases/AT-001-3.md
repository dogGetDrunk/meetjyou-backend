# AT-001-3: 후반 예외 발생 시 모집글·파티 원자적 롤백

- 요구사항: REQ-001, REQ-002
- Given:
  - H 작성 Post·Party capacity=4/joined=2, Busan, 2030-05-01~05-03 UTC, title=`Old title`
  - 기존 plan P0, isPlanPublic=true, 기존 compPreference 집합 C0를 DB에 커밋; H 소유 새 plan P1 준비
  - 테스트 전용 저장소 실패 주입: compPreference 저장 단계에서 RuntimeException("forced-comp-preference-failure") 발생하도록 설정
- When:
  - H가 capacity=6, Jeju, 2030-06-01~06-05 UTC, title=`New title`, plan=P1, 새 companionSpec으로 updatePost 호출
  - plan·Post 필드·Party 동기화 후 compPreference 단계에서 예외 전파
- Then:
  - 호출 실패, 쓰기 트랜잭션 전체 rollback
  - 새 트랜잭션 재조회에서 Post/Party 네 필드·title·content·isInstant·plan=P0·isPlanPublic=true 및 compPreference=C0가 사전 스냅샷과 일치
  - capacity=4/joined=2 유지, P1 연결/새 compPreference 일부 반영 없음
- 작성자: 보조 설계
- 코드 작성자: 별도 세션의 Terra
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/post/PostPartySyncIntegrationTest.kt`
- 테스트 종류: H2 통합(SpringExtension, 실제 서비스 트랜잭션 프록시)

## 구현·검증 지침
- mock 객체 필드 복원으로 rollback을 주장하지 않고 실패 트랜잭션 종료 후 별도 영속성 컨텍스트에서 검증
- 테스트 클래스 내부의 mock/spy 설정으로 실패 주입, production 실패 훅 추가 금지
- `./gradlew test --tests '*PostPartySyncIntegrationTest'`
