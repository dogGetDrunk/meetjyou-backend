# AT-003-3: 모집 완료 후 PENDING 승인과 COMPLETED 쓰기 거부

- 요구사항: REQ-003
- Given:
  - 시나리오 A: PLANNING, joined=1/capacity=4, H 호스트, U PENDING을 모집 완료 전에 생성
  - 시나리오 B: 별도 파티 progressStatus=COMPLETED, recruitmentStatus=CLOSED, Post.status=RECRUITMENT_COMPLETED
- When:
  - A: H가 모집 완료 커밋 후 기존 U 신청을 approveJoinRequest로 승인
  - B: H가 updatePostStatus(RECRUITING) 및 동일 RECRUITMENT_COMPLETED 재요청을 각각 실행
- Then:
  - A: 승인 성공, U=JOINED/joined=2, Post=RECRUITMENT_COMPLETED/Party=CLOSED 유지
  - B: 두 요청 모두 기존 validatePostWritable의 InvalidInputException, 어떤 상태 변화도 없음
  - 작성자가 아닌 사용자의 status 변경은 기존 PostUpdateAccessDeniedException 유지
- 작성자: 보조 설계
- 코드 작성자: 별도 세션의 Terra
- 보호 대상 테스트 파일:
  - `src/test/java/com/dogGetDrunk/meetjyou/post/UpdatePostStatusServiceTest.kt`
  - `src/test/java/com/dogGetDrunk/meetjyou/post/PostPartySyncIntegrationTest.kt`
- 테스트 종류: 단위 Kotest BehaviorSpec + H2 통합

## 구현·검증 지침
- D3은 approveJoinRequest 무변경 상태에서 실제 연동으로 증명; RECRUITMENT_COMPLETED와 PartyProgressStatus.COMPLETED 구분
- `./gradlew test --tests '*UpdatePostStatusServiceTest' --tests '*PostPartySyncIntegrationTest' --tests '*ApproveJoinRequestTest'`
